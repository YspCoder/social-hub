# Baidu Marketing API adapter

Package `social-hub/adapters/baiduads` implements account-scoped Baidu search
advertising workflows. Paid-media resources intentionally remain separate from
the common organic `Publisher`, `Fetcher`, `MediaUploader`, and messaging
interfaces.

## Configuration

Import the package for registration:

```go
import _ "social-hub/adapters/baiduads"
```

Configure one social-hub account for each Baidu advertiser username. Credential
values are resolved through `socialhub.SecretResolver` and are never accepted
as inline configuration values.

```yaml
adapter: baidu/marketing-api-2026-08
product: marketing-api
accounts:
  - id: baidu-search-main
    app_id: your-approved-app-id
    secret_ref: secret://baiduads/secret-key
    access_token_ref: secret://baiduads/access-token
    settings:
      user_name: advertiser-user-name
```

`access_token_ref` and `settings.user_name` are required for API calls. `app_id`
and `secret_ref` are additionally required when using the OAuth helper. One
authorized super-administrator access token can address managed child accounts
by configuring each child's `user_name` as a separate social-hub account.

API and OAuth base URL overrides exist only for tests and controlled gateways.
Redirects are rejected so the JSON-embedded access token or OAuth secret cannot
be forwarded to another origin.

## OAuth

`Adapter.OAuth` exposes the browser authorization URL, authorization-code
exchange, and refresh flow. The authorization URL requires an explicit scope,
callback, and one-time CSRF `state`; use the exact scope string generated by
Baidu's application-management page. The callback supplies `authCode` and
`userId`, which are both required by `OAuthClient.Exchange`.

Baidu's callback also contains a signature. Verify that signature and the
one-time `state` in the application callback before exchanging the code. The
adapter does not own callback state storage and does not treat receipt of a
callback as proof of authorization.

The current official OAuth document specifies `grantType: "auth_code"`. Access
tokens default to 24 hours and refresh tokens to 30 days, but the adapter uses
the returned `expiresIn` and `refreshExpiresIn` values. Refreshed credentials
must be persisted by the caller and made available through the configured
secret resolver; this initial adapter does not run a background token manager.

## Supported workflows

- Search Account information reads.
- Campaign get/list, paused-first create, typed update, and delete.
- AdGroup get/list by Campaign or AdGroup ID, paused-first create, typed update,
  and delete.
- Basic text Creative get/list, guarded create, full update, and delete.
- `OpenApiReportService` synchronous report data and asynchronous report tasks.
- OAuth token lifecycle, business-error mapping, `X-B3-Traceid`, and a typed
  default QPS policy.

Selected request fields are typed. `Fields map[string]any` is available for
documented product-specific fields such as targeting, tracking templates, and
conversion settings. Extension names must be lower-camel API identifiers and
cannot override IDs, credentials, state controls, or other adapter-owned
fields. Returned resources retain the complete provider object in `Raw`.

The initial adapter excludes Information Flow, shopping-specific services,
keywords, conversion assets, material upload, pre-review, and organic social
capabilities. Those products have distinct paths and permission contracts and
must be added as separately reviewed typed workflows.

## Off-first safety

Campaign creation always sends `pause: true`, and AdGroup creation always sends
`pause: true`. A provider response that does not confirm the paused state is
rejected as a contract error.

`addCreative` does not accept `pause`, while `updateCreative` requires the full
title, descriptions, and destination URLs. `CreateCreative` therefore performs
this sequence:

1. Read the parent AdGroup and require both matching Campaign ownership and
   `pause: true`.
2. Create the Creative without an unsupported `pause` field.
3. Submit a full Creative update with `pause: true` and require confirmation.

If step 3 fails, the method returns both the created Creative (including its ID)
and the error. The paused parent prevents delivery while the caller retries or
deletes the new Creative. This is a best-effort cross-request guard; callers
must serialize activation changes for the same hierarchy.

## Reports and limits

Synchronous reports require explicit `startRow` and positive `rowCount`.
Asynchronous tasks deliberately omit those pagination fields. Task IDs are
valid for 10 minutes, successful file URLs for about 5 minutes, and consumers
must use `dataStartRow` plus `tableHeader` instead of assuming a stable file
layout.

The published QPS defaults exposed by `DefaultQuotaPolicy` are:

| Resource | Get | Add | Update | Delete |
|---|---:|---:|---:|---:|
| Campaign | 100 | 30 | 30 | 10 |
| AdGroup | 50 | 30 | 100 | 30 |
| Creative | 100 | 50 | 100 | 30 |

Unlisted interfaces default to 10 QPS. Actual account grants remain
authoritative, so limiter configuration must be overridable. Baidu business
codes for frequency and quota exhaustion map to retryable
`socialhub.ErrRateLimited`; HTTP `Retry-After` and `X-B3-Traceid` are preserved
when present.

## Version and access

Baidu Marketing API does not publish a single global API version. The adapter
name `baidu/marketing-api-2026-08` and metadata value
`unversioned-2026-08` identify the contract verification date, not a provider
version. The official SDK release number `2023.0.0` is likewise an SDK release,
not an API version.

Production access requires Baidu developer registration, application review,
approved API permissions, and advertiser authorization. Product-level or
small-traffic fields may require additional approval from Baidu.
